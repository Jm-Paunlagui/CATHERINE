## 2. What dev.55 brought in (PR #18)

All new features are **opt-in**: existing models and queries keep working as before.

- **Statistics in `$group`:** `$countDistinct`, `$median`, `$stdDevPop` / `$stdDevSamp`, `$percentile`, `$push` / `$addToSet` / `$listAgg`.
- **Window and sort options:** LAG / LEAD defaults, IGNORE NULLS, RATIO_TO_REPORT, NULLS FIRST / LAST, `limit(n, { withTies: true })`.
- **Typed tables:** `defineTable(name, { COL: t.text(40), … })` gives type-checked filters, inserts and updates. `generateTableTypes(db, { tables })` writes the definitions of existing tables.
- **Migrations:** `createMigrator(db, { dir })` gives versioned files, a checksummed history (`MIRA_MIGRATIONS`), a lock and dry runs.
- **Relations:** `relations(Table, { orders: hasMany(…) })` and `find().include("orders")`, which fetch related rows in one statement.
- **JSON columns:** `t.json<T>()`, path filters and updates (`"DOC.a.b"`), `$elemMatch`, `$push` / `$pull`, `$jsonTable`.
- **Model conveniences:** `t.createdAt()` / `t.updatedAt()`, soft delete with `t.deletedAt()` (`withDeleted()`, `restore()`, `{ force: true }`), hooks, and `{ validate: true }` (`MiraValidationError`, 422).
- **Optimistic locking:** `t.version()`. A stale save throws `MiraConcurrencyError` (409).
- **Smaller additions:**
  - keyset paging with `.after(lastRow)`
  - `for await (const row of find())`
  - the ``sql`…` `` tag, where every value is bound
  - `onQuery()` statement events, which never carry bind values
- **Fixes also brought in (proven in Mira first):**
  - `insertMany` dropped columns that only later rows had, and failed (`NJS-011`) on `Buffer` values and on mixed number / string columns.
  - CLOB / BLOB values are read as `string` / `Buffer` in both driver modes.
  - In Thick mode, `TIMESTAMP WITH (LOCAL) TIME ZONE` values were shifted by the client's UTC offset.
  - `explainPlan` of a `find()` failed in Thick mode.
  - `$lateralJoin` with a limit returned wrong rows on 23ai.

Full details are in Mira's `CHANGELOG.md` (the 2.0.1 and 2.1.0 sections) and in the GitHub release `v2.1.0`.

### Behaviour changes, and why they are safe here

| Change | Checked in CATHERINE |
|---|---|
| CLOB / BLOB fetched as `string` / `Buffer` | The only CLOB reader (`serverAlertLog`, `data-purge` on `DETAILS`) already used `fetchInfo` STRING. There are no `getData()` calls |
| Thick-mode sessions open at UTC (`ORA_SDTZ=+00:00`, unless already set) | No session-time SQL (`CURRENT_TIMESTAMP`, `LOCALTIMESTAMP`, …) and no zoned timestamp columns. `SYSTIMESTAMP` and `$now` are unchanged |
| A filter key with a dot is now a JSON path | No dotted filter keys in `src` |
| Thick mode warns when `poolMax` is greater than `UV_THREADPOOL_SIZE` | A log line only. `.env.example` already documents `UV_THREADPOOL_SIZE` |

Tests changed by the upgrade:
- `updateParser.test.ts` now uses `$bit` as its unknown operator, because `$push` is supported.
- The message snapshot gained 13 templates (additions only).

## 3. How to run and check

```bash
cd Backend
bun install
bun run typecheck && bun run lint && bun run test          # 4876 tests, fully mocked
# live: start Oracle (docker start oracle19c), then
bun server.ts                                              # http://localhost:2108, .env APP_DB_* → SAMPLE
```

- **Demo login:** `admin` / `manager` / `user`. The password is in `Backend/scripts/seed-template.ts` and uses **`@`**, not `&`. Failed sign-ins count toward the lockout. A CSRF failure does not.
- **Login flow for scripts:**
  1. `GET /api/v1/csrf/token` → `{ token }` plus a cookie.
  2. `POST /api/v1/auth/login` with header `x-csrf-token` and body `{ userId, password }`.
- **Expected startup warnings on the Mac:**
  - the Windows Instant Client path in `.env`, so Thin mode is used
  - the SMTP CA file
  - the database clock being UTC: Docker's setting, while CATHERINE expects Manila (+08:00)

## 4. Release convention (as followed for dev.53 to dev.55)

1. Commit the change on a branch.
2. Make a separate `chore(release): 1.0.0-dev.N` commit that:
   - bumps **both** `Backend/package.json` and `Frontend/package.json`
   - adds the entry with `ChangelogModel.create({ displayDate, version, title, type, message, whatChanged, authors, coAuthors })`, which writes `Backend/data/changelog.enc`
   - runs `bun run changelog:dump`, which refreshes `scripts/changelog-dump.json`
3. Run `bun scripts/verify-changelog-release.ts --ref HEAD --tag v1.0.0-dev.N`. It must print PASS.
4. Open a PR into `main` and merge it after CI. Tags are occasional: the last one is `v1.0.0-dev.51`.

## 5. Keeping the shared wrapper in sync with Mira

1. **Change Mira first.**
   - Write the failing test, then make the fix.
   - Run `bun run test:coverage` (100%) and `bun run sim` on Oracle 19c.
   - CI covers 23ai in Thin and Thick mode.
2. **Copy into CATHERINE as is:** `src/utils/oracle-mongo-wrapper/**` (tracked files only; Mira's `logs/` folder is git-ignored output) and `src/constants/messages/oracleWrapper.messages.ts`.
3. **Three-way merge, never overwrite:** `src/config/adapters/oracle.ts` and `src/constants/messages/oracle.messages.ts`.
   - Use `git merge-file <catherine> <mira at the last synced tag> <mira now>`.
   - **The base for the next sync is Mira `v2.1.0`.**
   - CATHERINE's adapter has its own metrics, watchdog, `RetryPolicy` and the NJS-040 acquire rule.
4. **In CATHERINE:**
   - Run typecheck, **lint**, test, and a live boot.
   - Update tests that pinned old behaviour, and the message snapshot (`messages.wave2.test.ts`; every argument must appear in its template's output).
   - Release as the next `dev.N`.
5. **ESLint runs only here.** Mira has no ESLint. If lint flags wrapper code, fix it **in Mira** and copy it back, so both copies stay identical (Mira PR #33 did this for 2.1).

## 6. Open items

- **Thick-mode smoke test on Windows.** The `.exe` runs Thick mode. dev.55 was checked live only in Thin mode on the Mac, although Mira's CI runs the wrapper in Thick mode on 23ai. On the Windows machine:
  1. Start the app and confirm `oracledb driver loaded (Thick mode)` in the log.
  2. Sign in, and open the audit log and data purge.
  3. Watch for the new `UV_THREADPOOL_SIZE` warning, and set it to at least `APP_POOL_MAX + APP_BULK_POOL_MAX` if it appears.
- **oracledb 7 upgrade.** CATHERINE is on 6.10; Mira is on 7.0.1. Do it as its own change: with 7, Thick mode needs Oracle Client 19c or later, so check the Instant Client the `.exe` ships with.
- **Mira's `mira` command line was not brought over.** Migrations and type generation are available in code (`createMigrator()`, `generateTableTypes()`). Add `bun` scripts if you want them on the command line.
- **Integrity registry:** empty in the template by design (`Object.freeze({})`). Each app registers its own tables.
- **Docker `oracle19c`** may still be running on the Mac. Stop it cleanly with `docker stop -t 120 oracle19c`. Without `-t`, Docker kills Oracle after 10 seconds and it recovers on the next start.
